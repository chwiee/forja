CAPÍTULO 06

Cobra: a casca do CLI testado

O Cobra organiza o CLI como uma árvore de *cobra.Command: a raiz forja e os filhos build, push, manifest, exists, inspect e version. Neste capítulo você escreve a casca. O motor de build entra no capítulo 9.

6.1 Os conceitos

Campo / funçãoPara que serve
Use, Short, Long, ExampleNome e textos do --help, montado pelo Cobra
ArgsValida argumentos posicionais: ExactArgs(1), MaximumNArgs(1), NoArgs
RunEA execução. Devolve error, que sobe até o main
Flags() / PersistentFlags()Flags só do comando / herdadas pelos filhos
MarkFlagRequiredTorna uma flag obrigatória (o -t do build)
StringArrayVarFlag repetível: --build-arg A=1 --build-arg B=2
PersistentPreRunERoda antes de qualquer subcomando: valida flags globais, cria clientes
SilenceUsage / SilenceErrorsNão despeja o help a cada erro; o main imprime o erro uma vez
OutOrStdout() / ErrOrStderr()Resultado no stdout, logs no stderr; no teste, ambos viram buffer
Stdout para resultado, stderr para log

O build do buildah imprime dezenas de linhas. Elas vão para o stderr; no stdout sai só BUILD OK ... ou o JSON. Assim, forja build -o json . > resultado.json gera um JSON limpo, que o CI consegue ler.
