CAPÍTULO 05

O projeto do zero

Um projeto Go é uma pasta com um go.mod. O layout segue o golang-standards/project-layout, só no que o forja precisa.

  1. Crie a pasta e o módulo (PowerShell): 
    mkdir C:\wb\golang\forja; cd C:\wb\golang\forja
go mod init github.com/chwiee/forja
git init
mkdir cmd\forja, internal\cli, internal\build, internal\registry, deploy, scripts
  2. Entenda cada pasta antes de escrever código: 
    forja/
├── cmd/forja/main.go          ponto de entrada (//go:build linux): só liga as peças
├── internal/cli/              comandos Cobra (a casca): build, push, manifest, scan, run...
├── internal/build/            único pacote que importa o buildah
│   ├── build.go               tipos compartilhados (todas as plataformas)
│   ├── build_linux.go         build, push, manifest e export (só Linux)
│   ├── hostnet_linux.go       rede "de mentira" para o buildah (cap. 10)
│   ├── defaults_linux.go      configuração embutida (cap. 13)
│   └── defaults/              policy.json e registries.conf embutidos
├── internal/scan/             Syft, Grype, Gitleaks, política e nota (cap. 11)
│   └── defaults/policy.yaml   política padrão embutida
├── internal/registry/         único pacote que fala com o registry
├── testdata/                  imagens-isca e Dockerfiles de teste
├── ci/                        forja.sh, cosign.sh e o teste no Kubernetes
├── .github/workflows/ci.yml   o CI do próprio forja (cap. 18)
├── examples/github-actions/   pipelines prontos para os times de aplicação
├── deploy/k8s-pod.yaml        pod de build no Kubernetes
├── scripts/forja.ps1          atalho para Windows
├── cosign.pub                 chave pública para verificar a imagem do forja
├── Dockerfile                 imagem multi-arch do forja
├── .gitattributes             força fim de linha LF (scripts rodam em Linux)
└── LICENSE

    internal/ é uma fronteira garantida pelo compilador: outro módulo não consegue importar nada dali.

  3. Defina a licença no primeiro commit. Sem ela, o go-licenses marca o próprio projeto como "Unknown" (cap. 12). O forja de referência usa Apache-2.0, a mesma do buildah.
  4. Um commit por capítulo daqui em diante, para você conseguir voltar quando algo quebrar.
