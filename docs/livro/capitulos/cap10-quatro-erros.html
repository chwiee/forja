CAPÍTULO 10

Quatro erros até funcionar

A primeira versão do forja compilou de primeira e falhou quatro vezes seguidas dentro da imagem distroless. Cada erro foi resolvido do mesmo jeito: copiar um trecho da mensagem, achar com git grep o código do buildah que a gera, ler e entender a condição. Esta é a parte mais importante do livro, porque é o que você vai fazer sozinho quando o seu código quebrar.

Erro 1 — sem permissão de mount

erro: build: mounting an overlay over build context directory: ... mount overlay: ... operation not permitted

Leitura: imagebuildah/build_linux.go, função platformSetupContextDirectoryOverlay. O buildah sempre monta um overlay por cima do diretório de contexto, para que um RUN não altere seus arquivos. Montar exige privilégio.
Correção: dar permissões ao container (primeiro --privileged, para ver funcionar; o mínimo real está no cap. 14).

Erro 2 — overlay sobre overlay

erro: build: mounting an overlay over build context directory: ... mount overlay: ... invalid argument

Leitura: o diretório temporário do overlay fica em /var/tmp, que está no disco do próprio container, que já é um overlay. O kernel não aceita overlay em cima de overlay.
Correção: /var/tmp num volume (-v forja-tmp:/var/tmp; no Kubernetes, um emptyDir). A pasta do Windows montada em /workspace funcionou como camada de baixo sem problema.

Erro 3 — o netavark que nunca seria usado

erro: build: creating build container: could not find "netavark" in one of [/usr/local/libexec/podman ...]

Leitura: new.go chama getNetworkInterface sempre que options.NetworkInterface é nil. Em vendor/go.podman.io/common/libnetwork/network/interface.go, o único backend aceito é o netavark, e o binário tem que existir, mesmo que nunca seja executado. Configurar só NamespaceOptions com a rede do host não bastou.
Correção: preencher NetworkInterface com a implementação hostNetwork (cap. 9.3).

Erro 4 — compilou, mas não funciona

OK: 13 MiB in 24 packages
process exited with error: parsing PID "": strconv.Atoi: parsing "": invalid syntax

O RUN apk add rodou: os pacotes foram instalados. O erro veio depois.
Leitura: git grep 'parsing PID' leva a go.podman.io/storage/pkg/unshare/unshare_linux.go: o processo pai espera o filho escrever o próprio PID num pipe. Quem escreve é _containers_unshare(), uma função em C chamada por um __attribute__((constructor)) em unshare_cgo.go, que só existe com a build tag cgo. O primeiro Dockerfile compilava com CGO_ENABLED=0, então ninguém escrevia o PID.
Correção: CGO_ENABLED=1. A primeira versão linkou com a glibc e usou distroless/base (84,7 MB), o que prendeu o binário a imagens com glibc nova. A solução definitiva, estático com musl, está no capítulo 13.

A lição

"Compila" não prova nada sobre bibliotecas que dependem do sistema operacional. O buildah compilado sem cgo passou no go build, no go vet e no cross-compile, e só falhou executando um RUN de verdade. Para esse tipo de lib, o único teste que vale é rodar no ambiente-alvo.
