CAPÍTULO 00

Como usar este livro

Este livro constrói o forja v0.4, que está em produção no repositório chwiee/forja. É um CLI que recebe o Dockerfile da aplicação e executa exists → build → scan → gate → push: builda com a biblioteca do buildah, escaneia CVEs (Syft e Grype), secrets (Gitleaks) e configuração, dá uma nota de 0 a 100, e só publica se a imagem passar. Publica no GHCR ou no ECR central com --registry. É um binário estático que roda em qualquer imagem Linux, em amd64 e arm64, sem Docker nem daemon dentro dele. A imagem oficial é assinada com cosign.

Tudo o que aparece como testado foi executado e as saídas são reais. O CI do repositório repete os testes a cada push, em runners amd64 e arm64 nativos, num pod do Kubernetes e contra um ECR emulado: o capítulo 18 mostra o resultado. O que depende de algo que não existe aqui (um nó EKS, a conta AWS real) aparece como não testado.

O roteiro de estudo: 4 etapas que compilam

Os capítulos mostram o código final de cada arquivo. Se você digitar o capítulo 6 e tentar compilar, não vai conseguir: o root.go final já depende do motor de build, do scan e dos registries, que só chegam nos capítulos 9, 11 e 19. Para estudar passo a passo, o repositório tem o branch estudo, que reconstrói o forja em 4 etapas. Cada etapa compila, tem os testes passando e foi validada de verdade:

O jeito de estudar cada etapa:

  1. Leia os capítulos da etapa.
  2. Veja o que a etapa acrescenta à anterior: git diff estudo-e1 estudo-e2. É o "o que mudou e por quê" de cada passo, arquivo por arquivo.
  3. Digite essas mudanças no seu projeto (em C:\wb\golang\forja, por exemplo), sem copiar.
  4. Valide com os comandos do README da etapa (git show estudo-e2:README.md) e compare a saída.
  5. Compare com a referência quando travar: git diff estudo-e2 -- internal/ a partir do seu código.
git clone https://github.com/chwiee/forja.git && cd forja
git checkout estudo-e1                 # o código da etapa 1
git diff estudo-e1 estudo-e2 --stat    # o que a etapa 2 acrescenta
git show estudo-e2:README.md           # como validar a etapa 2
Regra de ouro

Digite o código em vez de copiar. Quando algo quebrar, antes de olhar a referência, procure o sintoma no Apêndice A: quase todo erro que você vai ver já aconteceu na construção do forja e está lá com a causa e a correção.
