CAPÍTULO 07

Importando uma lib, em detalhe

"Importar a classe do buildah" são três passos: declarar o módulo no go.mod, baixar e verificar o código, e escrever o import. O go get faz os dois primeiros.

7.1 O que acontece num go get

  1. Resolve a versão. @v1.45.1 fixa; @latest pega a maior tag estável.
  2. Baixa pelo proxy proxy.golang.org (GOPROXY), que guarda cópias imutáveis.
  3. Confere o hash no banco público sum.golang.org (GOSUMDB). Se alguém reescrever uma tag no GitHub, o build falha.
  4. Grava a versão no go.mod e os hashes de tudo no go.sum.

Uma linha de go get do buildah trouxe mais de 430 módulos (go list -m all). Syft, Grype e Gitleaks levaram o forja v0.3 a 983, e a imagem de 53,9 MB para 142 MB. Cada um é código de terceiros que vai para dentro do seu binário. Por isso o capítulo 12 roda govulncheck e go-licenses.

7.3 Importe o pacote mais estreito

No primeiro protótipo, o uso de alltransports.ParseImageName puxou os transports de storage, SIF e OpenShift, cada um com suas dependências, e o build falhou com missing go.sum entry para módulos que o código nem usava. Trocar por docker.ParseReference resolveu. Antes de importar um pacote "guarda-chuva", procure o específico.

7.5 A pegadinha do GOOS com ferramentas

Para auditar o código Linux estando no Windows, a primeira tentativa foi esta:

GOOS=linux go run golang.org/x/vuln/cmd/govulncheck@v1.1.4 ./...
exec: "...\go-build\...\govulncheck": executable file not found in %PATH%

O GOOS=linux também valeu para compilar o próprio govulncheck, que virou um binário Linux e não roda no Windows. O certo é instalar a ferramenta para o seu sistema e aplicar o GOOS só na análise:

go install golang.org/x/vuln/cmd/govulncheck@v1.1.4
GOOS=linux govulncheck -tags "containers_image_openpgp exclude_graphdriver_btrfs" ./...

No PowerShell, a segunda linha fica: $env:GOOS="linux"; govulncheck ...; Remove-Item Env:GOOS.

7.6 replace e vendor

replace go.podman.io/buildah => ../estudos/buildah aponta o módulo para um clone local, onde você pode colocar prints dentro do buildah. Nunca faça commit disso. go mod vendor copia as dependências para o repositório, o que permite builds sem internet e diffs auditáveis, ao custo de um repo bem maior.

7.7 O spike: quatro bibliotecas grandes no mesmo go.mod

O maior risco do projeto era juntar buildah (ecossistema go.podman.io) com Syft e Grype (ecossistema Docker/containerd) num binário só. O spike foi um go get das quatro e um go mod tidy:

go get github.com/anchore/grype@latest github.com/anchore/syft@latest \
       github.com/zricethezav/gitleaks/v8@latest github.com/anchore/clio@latest
go: added github.com/anchore/grype v0.119.0
go: added github.com/anchore/syft v1.52.0
...
go mod tidy                          (sem conflito)
go vet ./...                         (Windows: ok)
GOOS=linux CGO_ENABLED=0 go vet ./... (Linux: ok)
docker build                         (estático com musl, amd64 e arm64: ok)

Não houve conflito: a seleção de versão mínima do Go (MVS) escolheu, para cada módulo compartilhado, a maior versão pedida, e todas eram compatíveis. Isso não é garantido; por isso o spike vem antes de escrever lógica. Se tivesse dado conflito, o plano B era rodar o Grype como binário separado.
