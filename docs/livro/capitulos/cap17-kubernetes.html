17.3 Os dois resultados

No kind do Docker Desktop, com hostUsers: false (Kubernetes 1.36.4, containerd 2.3.4, kernel 6.18):

@@saida k8s-local.txt@@
$ kubectl get pod forja-build -o jsonpath=...
hostUsers=false readOnlyRoot=true caps=["SYS_ADMIN","CHOWN","DAC_OVERRIDE","FOWNER","FSETID","KILL","NET_BIND_SERVICE","SETFCAP","SETGID","SETPCAP","SETUID","SYS_CHROOT"]

Com hostUsers: false, o kubelet recusa o pod se o runtime não suportar user namespace. Como o pod chegou a Succeeded, o isolamento foi aplicado.

No kind do CI, o primeiro teste falhou antes de o forja iniciar, e não por causa dele:

Failed to create pod sandbox: ... runc create failed: unable to start container process:
error during container init: error mounting "sysfs" to rootfs at "/sys": ... operation not permitted

No runner, o kind é um container dentro do Docker, e o sandbox do pod (o container pause) não consegue montar o /sys dentro do user namespace nesse aninhamento. Num nó EKS não existe esse aninhamento. O CI então remove só a linha hostUsers (com o motivo comentado no workflow) e prova todo o resto: capabilities, raiz somente leitura, volumes e AppArmor Unconfined. Resultado: fase do pod: Succeeded, nota 92, PUSH OK (capítulo 18).

Pod Security Admission

Das 12 capabilities, só SYS_ADMIN fica fora do nível baseline, e o AppArmor Unconfined também. O namespace dos builds precisa do nível privileged ou de uma exceção no Kyverno/Gatekeeper. Isolar esse namespace é parte do desenho.

Validar no EKS antes de produção

O hostUsers: false foi provado no kind do Docker Desktop. No EKS, ele depende da versão do Kubernetes (1.33 ou mais nova), do containerd 2.x e do kernel do nó (Amazon Linux 2023 ou Bottlerocket recentes). Rode o ci/k8s-e2e.yaml uma vez em cada node group, amd64 e Graviton, antes de liberar.

ARC e o shell

No Actions Runner Controller em "kubernetes mode", os steps run: precisam de shell na imagem do job, e o distroless não tem. Opções: o runner dispara o pod do forja com kubectl (como o job k8s do CI faz); usar a variante :debug do distroless; ou colocar o forja na imagem do runner com um COPY --from (capítulo 13.4).
