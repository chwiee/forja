Rodando no Windows testado

No Windows, o forja tem dois modos: a imagem distroless via Docker Desktop, para build e push, e o forja.exe nativo, para exists e inspect, que não precisam do buildah.

15.2 O laboratório: registry local e o Dockerfile do usuário

PowerShell — uma vez
docker network create lab
docker run -d --name registry --network lab -p 5000:5000 docker.io/library/registry:3

O projeto de exemplo tem um Dockerfile comum, com FROM de nome curto, ARG, RUN com rede, COPY e USER. É o tipo de arquivo que um usuário do forja escreveria:

C:\wb\estudos\forja-lab\app\Dockerfile
@@arquivo testdata/app/Dockerfile@@
C:\wb\estudos\forja-lab\app\hello.sh
@@arquivo testdata/app/hello.sh@@
Fim de linha

Salve o hello.sh com fim de linha LF, e não CRLF. No VS Code, é o indicador "CRLF" no canto inferior direito. Com CRLF, o shell do Alpine não encontra /bin/sh\r e o container falha ao iniciar.

@@saida windows-native.txt@@

O binário do Windows tem 12 MB, porque o buildah não entra nele (o build_other.go é que é compilado).

Vírgula no PowerShell

No PowerShell, --platform linux/amd64,linux/arm64 sem aspas vira uma lista e chega ao forja como dois argumentos: erro: accepts at most 1 arg(s), received 2. Use aspas: --platform "linux/amd64,linux/arm64". No bash, com ou sem aspas, funciona.

15.5 O scan no Windows

O forja run e o forja scan funcionam pela mesma função forja do PowerShell. O banco de CVEs fica no volume forja-tmp, então só a primeira execução baixa: aqui, 75 s na primeira e 5 s nas seguintes. O forja.exe nativo não faz scan. Parecia que faria, porque Syft, Grype e Gitleaks são Go puro, mas o teste mostrou outra coisa: a biblioteca de camadas do Syft grava arquivos com : no nome (0-sha256:...), e o Windows recusa (rename ... Parâmetro incorreto). Em vez de deixar o usuário cair nesse erro, o forja recusa na hora: scan não funciona no Windows nativo (...); rode a imagem do forja com Docker. Há um teste para isso (TestScanRefusesNativeWindows).

15.6 ECR a partir do Windows

A função forja repassa ao container as variáveis AWS_* e FORJA_ECR_* que existirem na sessão. Ela usa -e NOME sem valor, então o segredo não aparece na linha de comando. Com isso, o --registry ecr funciona igual ao pipeline. Na sua máquina, a credencial vem das variáveis de ambiente: exporte as do seu perfil com aws configure export-credentials --format powershell | Invoke-Expression. O container não lê o ~/.aws, então perfis SSO precisam ser exportados assim. Teste com o floci numa rede própria:

@@saida windows-ecr.txt@@

Duas observações do teste. Primeiro, a imagem ghcr.io/chwiee/forja é privada, então o Docker precisa de docker login ghcr.io com um token que tenha read:packages; sem isso, o erro é unauthorized. Segundo, cada chamada é um container novo, mas o volume forja-storage guarda as imagens entre chamadas. Mesmo assim, prefira forja run (ou build --push) a um build seguido de push.
