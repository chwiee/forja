O CI do forja no GitHub testado

O repositório chwiee/forja (privado) tem um único workflow, com cinco jobs em sequência. Cada push na main prova de novo tudo o que este livro afirma, e em hardware real.

18.2 Assinatura sem log público

O modo keyless do cosign grava a identidade do workflow (inclusive o nome do repositório) no Rekor, um log público. Para um repositório privado isso vaza informação, então o forja assina com chave própria e sem log. A chave privada e a senha ficam nos secrets COSIGN_PRIVATE_KEY e COSIGN_PASSWORD; a pública está versionada em cosign.pub. Uma lição do caminho: no cosign v3, --tlog-upload=false sozinho é recusado; é preciso também --use-signing-config=false. Testado aqui antes do CI: a assinatura confere com a chave certa e é recusada com outra chave (accepted signatures do not match threshold).

docker run --rm -v "$PWD:/w" -w /w ghcr.io/sigstore/cosign/cosign:v3.1.3 \
  verify --key cosign.pub --insecure-ignore-tlog ghcr.io/chwiee/forja:0.3.0

18.3 O que o CI encontrou que o Windows não mostrava

Tudo passava no Windows e no Docker Desktop. O CI achou três erros, e cada um foi reproduzido aqui antes de ser corrigido:

OndeErroCausaCorreção
job testbtrfs/version.h: No such file or directorysó no Linux com cgo o driver btrfs é compiladotag exclude_graphdriver_btrfs no vet e nos testes (cap. 12.4)

(was soft=65536,hard=65536): operation not permittedo buildah dá a cada RUN nofile=1048576 (run_linux.go, addRlimits); subir acima do teto exige CAP_SYS_RESOURCE. O Docker Desktop já tem teto 1048576, por isso não apareciao forja passa o teto atual (currentUlimits) + teste; reproduzido com docker run --ulimit nofile=65536:65536
antecipado para o k8scarregando banco de CVEs: database does not existcom a raiz somente leitura, o Grype baixa o banco num temporário em /tmp, que não é gravável; a mensagem enganaENV TMPDIR=/var/tmp na imagem; reproduzido com docker run --read-only

O erro do limite de arquivos também trouxe uma boa notícia: no runner arm64 ele aconteceu depois do reexec do buildah. Ou seja, o forja arm64 nativo passou exatamente pelo ponto que falhava na emulação do capítulo 16.4.

Uma lição de ferramenta: o git push ficava minutos parado no Windows porque o Git Credential Manager abria uma janela escondida. Com o helper do GitHub CLI (git config credential.helper '!gh auth git-credential'), o push levou 3 segundos.

Imagem privada para outros repositórios

O pacote ghcr.io/chwiee/forja nasce privado, ligado ao repositório. Para outros repositórios usarem, dê acesso em Package settings → Manage Actions access, ou torne o pacote visível para a organização. A aba Security com o SARIF, em repositório privado, exige GitHub Advanced Security.
